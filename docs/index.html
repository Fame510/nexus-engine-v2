The crisis

THE WEB CHANGES. YOUR SYSTEM FINDS OUT LAST.

Most browser automation gives you a page. It does not give you an accountable run: who asked, what policy allowed it, what changed, which artifact proves it, or whether a retry silently charged you twice.

Broken selectors

DOMs move, SPAs hydrate late, lazy content arrives after the first response, and a green HTTP status proves almost nothing.

Volatile jobs

In-memory status disappears on restart. Duplicate retries become duplicate work. One worker cannot become a platform.

Unsafe execution

Unbounded navigation, private targets, arbitrary scripts, open WebSockets, and missing quotas turn scraping into an incident surface.

The solution

ONE API. TWO ENGINES. A RUN YOU CAN DEFEND.

curl -X POST http://localhost:3000/v1/jobs \\
  -H 'Authorization: Bearer nx_your_key' \\
  -H 'Idempotency-Key: catalog-price-2026-09-09' \\
  -H 'Content-Type: application/json' \\
  -d '{
    "url": "https://example.com/product",
    "engine": "playwright",
    "mode": "headless",
    "extract": {"schema": {"price": {"selector": ".price", "transform": "number"}}},
    "artifacts": {"html": true, "screenshot": true}
  }'

Durable by default

BullMQ and Redis provide retries, backoff, cancellation, stalled-job recovery, and retention across workers.

Policy before browser

Private-network rejection, action limits, script denial, API keys, tenant isolation, quotas, and rate limits run before execution.

Evidence, not vibes

Return structured values with content hashes, screenshots, HTML, metadata, and a lifecycle trail that can be replayed.
